Section 1

Architecture Overview

The site is a full-stack web application built on three layers: a Next.js frontend/backend, Supabase for authentication and data, and Vercel for hosting.

⚡ Next.js 16

App Router with server and client components. Server Components fetch data; Client Components handle interactions. Route protection via proxy.ts.

🗄️ Supabase

Handles user authentication (JWT sessions), the profiles database table, Row Level Security policies, and hCaptcha token verification.

🌐 Vercel

Serverless hosting with auto-deploy on every GitHub push. Static pages are prerendered at build time; dynamic pages render on demand per request.

🔒 Row Level Security

Database enforces that each player can only read and write their own profile row. Admins bypass this via the is_admin() function.

🤖 hCaptcha

Bot protection on login and registration. The token is generated client-side, then verified server-side by Supabase before auth operations complete.

📦 GitHub

Source code at ptkoroma/dmv-allstars. Every push to the develop branch triggers an automatic Vercel deployment.

Section 4

Authentication Flow

Registration Flow

  • User fills Step 1: name, email, password, confirm password
  • Client validates passwords match and length ≥ 6
  • User fills Step 2: position, age group, experience, parent info
  • User completes hCaptcha challenge
  • Client calls supabase.auth.signUp() with captchaToken
  • Supabase verifies hCaptcha token server-side
  • Supabase creates row in auth.users
  • Client inserts row into profiles table (RLS enforced)
  • User redirected to /dashboard

Login Flow

  • User enters email and password
  • User completes hCaptcha challenge
  • Client calls supabase.auth.signInWithPassword() with captchaToken
  • Supabase verifies hCaptcha token server-side
  • Supabase validates credentials, issues JWT session cookie
  • proxy.ts reads the JWT on every request
  • If valid → allows access to /dashboard or /admin
  • If invalid/expired → redirects to /login
  • Admin role verified server-side before rendering /admin
Section 5

Security Audit

The following findings were identified through a review of the authentication and registration code, database schema, and route protection logic.

High Severity

Weak Password Minimum (6 Characters)

High

Locationapp/register/page.tsx:51

The only password requirement is a minimum of 6 characters with no complexity rules enforced. This permits passwords like 123456 or abcdef, which are trivially crackable. For a site storing minors' personal data and emergency contact information, this is a significant risk.

RiskAccount takeover via brute force or credential stuffing attacks.

Orphaned Auth User on Profile Insert Failure

High

Locationapp/register/page.tsx:88–109

If supabase.auth.signUp() succeeds but the subsequent profiles table insert fails, a user exists in auth.users with no profile row. This user can log in but the dashboard will show no data and errors will occur. There is no cleanup or retry mechanism.

RiskBroken user state; user cannot access dashboard; admin cannot see the player.

Medium Severity

Email Duplicated in Profiles Table

Medium

Locationsupabase-schema.sql:15 and app/register/page.tsx:92

The profiles table stores email as a separate column copied from the form at registration time. If a user later changes their email via Supabase Auth, the profiles.email becomes stale and out of sync with auth.users.email, leading to incorrect data displayed in the admin dashboard.

RiskData inconsistency; admin sees wrong email for a player.

No Password Strength Feedback

Medium

Locationapp/register/page.tsx — Step 1 form

Users receive no visual feedback about password strength while typing. There is no indicator showing whether a password is weak, moderate, or strong, and no guidance on what makes a good password. Users will naturally choose the shortest password accepted (6 chars).

RiskPoor password hygiene across the user base increases account compromise risk.

No "Forgot Password" Recovery Flow

Medium

Locationapp/login/page.tsx — missing link

There is no "Forgot Password?" link on the login page. Users who forget their password have no self-service recovery path and must contact an admin. Supabase provides a resetPasswordForEmail() method ready to use.

RiskPoor user experience; players locked out permanently; admin burden.

No Phone Number Validation

Medium

Locationapp/register/page.tsx:236 — phone, parentPhone fields

Phone fields use type="tel" with a placeholder but no pattern or validation. Any string is accepted — letters, symbols, or empty strings — making emergency contact data unreliable.

RiskUnusable emergency contact data; inability to reach parents in emergencies.

Low Severity

No Terms of Service / Privacy Policy Acceptance

Low

Locationapp/register/page.tsx — Step 2

Registration collects personal data including minors' dates of birth, parent names, and emergency contacts, but there is no checkbox requiring users to accept a Privacy Policy or Terms of Service. This may create legal exposure under COPPA (for users under 13) and general data protection obligations.

RiskLegal/compliance exposure for collecting children's data without consent.

No Age Verification for Minors

Low

Locationapp/register/page.tsx:219

Date of birth is collected but not validated on the client. A user could enter a date making them under 13 with no additional parental consent flow triggered, which may conflict with COPPA requirements.

RiskCOPPA compliance gap; collecting children's data without verified parental consent.

No Password Visibility Toggle

Info

Locationapp/login/page.tsx and app/register/page.tsx

Password fields have no show/hide toggle. Users on mobile or those making typos have no way to verify their password before submitting, leading to failed logins and re-registration attempts.

RiskMinor UX friction; no direct security impact.

Section 6

Security Recommendations

1. Enforce Strong Passwords

Increase minimum to 8 characters and require at least one uppercase, one number, and one special character. Add a real-time strength meter.

In register/page.tsx replace the length check with:
/^(?=.*[A-Z])(?=.*\d)(?=.*[!@#$]).{8,}$/.test(password)

2. Fix Orphaned Auth Users

Wrap auth signup and profile insert in a try/catch. If the profile insert fails, call supabase.auth.admin.deleteUser() to clean up, or use a Supabase Database Function triggered by the auth.users insert.

Better: use a Supabase trigger on auth.users to auto-create the profile row server-side, removing the client-side race condition entirely.

3. Remove Email from Profiles

Drop the email column from profiles. Always read email from auth.users via user.email from the session, which stays authoritative after any email change.

ALTER TABLE profiles DROP COLUMN email;

4. Add Forgot Password

Add a "Forgot password?" link on the login page pointing to a /forgot-password page that calls supabase.auth.resetPasswordForEmail(email). Supabase sends a secure reset link automatically.

Also create /reset-password to handle the callback and let users set a new password via supabase.auth.updateUser().

5. Validate Phone Numbers

Add a pattern attribute and client-side validation using a regex that accepts standard US phone formats.

pattern="[\+]?[(]?[0-9]{3}[)]?[-\s\.]?[0-9]{3}[-\s\.]?[0-9]{4}"

6. Add Terms & Privacy Checkbox

Add a required checkbox on Step 2 of registration: "I agree to the Terms of Service and Privacy Policy." Gate the submit button on this being checked. Create minimal /terms and /privacy pages.

For players under 13 (detected from date of birth), require a parent email and send a parental consent email before activating the account.

7. Add Password Visibility Toggle

Add an eye icon button to all password inputs that toggles the input type between password and text.

Use useState for each field: const [show, setShow] = useState(false) → type={show ? 'text' : 'password'}

8. Enable Supabase Auth Rate Limiting

In Supabase → Auth Settings, configure the rate limits for sign-in and sign-up attempts per hour per IP. The defaults are permissive — tighten them for a site with youth players.

Recommended: max 5 sign-in attempts per hour per IP. This works alongside hCaptcha as a second line of defence.

Quick SEO Fixes — Code Examples

Per-Page Metadata

Add to each page.tsx — e.g. app/about/page.tsx:

export const metadata = {
  title: 'About Us | DMV All Stars FC',
  description: 'Learn about DMV All Stars FC, est. 2015 — developing elite soccer talent in the Washington DC metro area.',
  openGraph: {
    title: 'About DMV All Stars FC',
    images: ['/soccer.png'],
  },
}

Sitemap + Robots

Create app/sitemap.ts:

export default function sitemap() {
  return [
    { url: 'https://dmv-allstars.com', changeFrequency: 'weekly', priority: 1 },
    { url: 'https://dmv-allstars.com/about', priority: 0.8 },
    { url: 'https://dmv-allstars.com/gallery', priority: 0.7 },
  ]
}

JSON-LD Structured Data

Add to app/page.tsx for rich search results:

<script type="application/ld+json">
{ "@context": "https://schema.org",
"@type": "SportsOrganization",
"name": "DMV All Stars FC",
"sport": "Soccer",
"url": "https://dmv-allstars.com",
"foundingDate": "2015",
"address": { "@type": "PostalAddress", "addressLocality": "Washington", "addressRegion": "DC" } }
</script>

Robots.txt

Create app/robots.ts to block private routes:

export default function robots() {
  return {
    rules: { userAgent: '*', allow: '/', disallow: ['/dashboard', '/admin'] },
    sitemap: 'https://dmv-allstars.com/sitemap.xml',
  }
}
